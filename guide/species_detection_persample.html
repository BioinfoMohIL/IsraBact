Species Detection Per Sample

Reference guide for running Species_Detection_PerSample_MOH on Terra — Kraken2-based taxonomic classification of sequencing reads, from BaseSpace import to detected species.

read1 + read2→Kraken2 2.17.1→kraken2_species_detected

🧬 Quick start

01
Select workflow

Find the workflow in Terra

In Terra, select Species_Detection_PerSample_MOH. It's available from either repository:

  • Dockstore: Species_Detection_PerSample_MOH
  • GitHub: wf_kraken2.wdl
02
Import reads

Get sequencing reads into the workspace

Species detection needs FASTQ files already present in the Terra workspace. If they aren't there yet:

  1. Run the Basespace_Fetcher_MOH workflow.
  2. Wait until FASTQ files are successfully imported.
  3. Open the Terra workspace Data table.
03
Configure

Select samples and configure inputs

From the Data table, select the samples to analyze. The default sample identifier is tmp_id.

Workflow inputDescription
read1Forward paired-end FASTQ file (R1)
read2Reverse paired-end FASTQ file (R2)
sample_idSample identifier (default: tmp_id)
04
Launch

Launch execution

Launch

Terra will automatically:

  • Create the Google Cloud Batch job.
  • Allocate computing resources.
  • Pull the Kraken2 Docker image.
  • Download and prepare the Kraken2 database.
  • Run species classification.
  • Store results in the workspace.

Workflow description

The workflow performs species detection using Kraken2. Input sequencing reads are classified against a predefined Kraken2 database.

Automatically detected

  • Paired-end reads.
  • Compressed FASTQ files (.gz).
  • The Kraken2 database location.

Kraken2 database

The Kraken2 database is stored in the Terra workspace Google Cloud bucket. Users do not need to upload or manage the database manually.

gs://fc-5d4556f8-3de6-4709-85da-11445772644d/db/
minikraken2_v2_8GB_201904_UPDATE.tar.gz

During execution

  1. The database archive is downloaded automatically.
  2. The archive is extracted locally on the compute VM.
  3. Kraken2 runs using the extracted database.

Docker environment

The workflow uses Kraken2 version 2.17.1 from Google Artifact Registry:

us-docker.pkg.dev/general-theiagen/theiagen/kraken2:2.17.1

Using Google Artifact Registry avoids Docker Hub pull-rate limitations during large Terra executions.

⚠️ Troubleshooting

Kraken database error

If Kraken2 reports:

database does not contain necessary file taxo.k2d

The database directory is incorrect. The folder provided to Kraken2 must contain:

kraken_db/ └── minikraken2_v2_8GB_201904_UPDATE/     ├── hash.k2d     ├── taxo.k2d     └── opts.k2d

Workflow automation

The workflow is designed for non-technical users. After FASTQ import, users only need to select samples and click Launch. All database handling, computation setup, and Kraken2 execution are automated.
