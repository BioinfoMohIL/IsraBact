INTRO

What is chewBBACA?

chewBBACA is a bioinformatics tool for large-scale bacterial genome characterisation using cgMLST (core genome MultiLocus Sequence Typing). It compares thousands of genes (loci) across bacterial strains to produce a unique "genetic barcode" per strain — invaluable for outbreak detection, epidemiological surveillance, and clone tracking.

Adapted schema

Species-specific reference database of loci. Pre-computed and provided as a .zip file by the bioinformatics team.

AlleleCall

Core step: compares each assembly against the schema to assign an allele number to every locus per strain.

ExtractCgMLST

Filters loci present in at least X% of strains to define the "core genome" used for downstream analysis.

Output

A TSV table — one row per strain, one column per locus — ready for GrapeTree or PHYLOViZ.

01

What the workflow does

1

Input validation

The workflow checks that you have provided either assemblies or assemblies_zipped — but not both. If neither or both are given, it stops immediately with a clear error message.

2

AlleleCall

Decompresses the adapted schema, prepares the assembly files, and runs chewBBACA to assign an allele to each locus for each strain. Sample names are automatically cleaned (extension stripped, first token kept).

3

ExtractCgMLST

Extracts the core genome at each threshold defined in cgmlst_thresholds (e.g. 95%, 99%, 100%). One result file is produced per threshold.

02

Workflow parameters

Required inputs
assemblies
required *
List of .fasta / .fa / .fna files — one per strain.
specie_prefix
required *
"CA" | "EC" | "F-EC" | "SA" | "SO" | "ST" | "NM" | "M" | "LF" | "LC" | "LG".
Don't forget the quotation marks


AlleleCall — advanced parameters
allele_call_mode
4
Mode 4 = fast mode (recommended for routine use). Mode 1 is more thorough but significantly slower — only use it for final publication-grade analyses.
allele_call_bsr
0.6
BLAST Score Ratio threshold to validate an allele match. Value between 0 and 1 — do not change unless you know what you are doing.
allele_call_minimum_length
0
Minimum allele length in base pairs. 0 means no filter is applied — all allele lengths are accepted.
allele_call_translation_table
11
Genetic code used for translation. 11 is the standard table for bacteria and archaea. Only change for unusual organisms (e.g. Mycoplasma = 4).
allele_call_size_threshold
0.2
Allowed size variation (±20%) relative to the reference allele length. Alleles deviating beyond this threshold will be rejected as ASM or ALM.
allele_call_cds_input
false
Set to true only if your input files already contain annotated CDS sequences. Leave as false in most cases.
allele_call_no_inferred
false
If true, disables automatic addition of newly inferred alleles to the schema. Useful for strictly reproducible results across runs.


ExtractCgMLST
cgmlst_thresholds
[0.95, 0.99, 1]
List of presence thresholds. 0.95 means "keep loci present in at least 95% of strains". One output file is generated per threshold.
03

How to run it on Terra

1

Open your Terra workspace

Go to app.terra.bio and sign in with your Google account. Select the shared workspace provided by your team.

2

Find the workflow

If this is your first time, import it from Dockstore.org and click Launch with Terra.

In the workspace menu, click Workflows. You will find wgMLST_ChewBBACA_MOH already imported and ready to configure.

3

Upload the adapted schema to the workspace bucket

Already done for you. The workflow automatically selects the correct schema based on the species prefix in your input file names — no manual configuration needed.

All adapted schemas have been downloaded from chewBBACA Schema Stats (Compressed version) and stored in a shared bucket accessible from the workspace: 

IMOH-Workspace-Sequencing-Data/datasets/chewbbaca
4

Configure the inputs

Click on the workflow, then fill in the fields in the interface

Task name Variable Type Input value
wf_chewbbaca assemblies Array[File] this.seq_datas.assembly_fasta
wf_chewbbaca specie_prefix String "CA"
All other parameters are defaults .
5

Launch and monitor

Click Run Analysis. Terra displays the progress of each task in real time. If a task turns red, click on it to read the error log.

Expect 30–90 minutes depending on the number of strains and schema size. Terra can send an email notification when the job completes.
6

Retrieve your results

Once complete, output files appear under Job History → click the job → Outputs. Download them directly from the browser or copy their gs:// path for downstream tools.

04

Output files

chew_alleles

Main TSV table: one row per strain, one column per locus. Contains cleaned allele numbers ready for analysis.

chew_visualization_zip

Archive with cgMLST results filtered at each threshold — ready for GrapeTree or PHYLOViZ.

fail_logs

Only present if the workflow fails input validation. Contains the error message explaining what went wrong.

chew_version

Version string (3.3.10). Useful for traceability and reporting in publications.

You must provide either assemblies (a list of individual files) or assemblies_zipped (a single archive) — never both at the same time. The workflow will stop immediately with an error message if both fields are filled in.
